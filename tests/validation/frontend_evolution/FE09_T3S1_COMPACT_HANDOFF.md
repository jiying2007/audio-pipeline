## Exact compact architecture / 精确结构与所有权

Noninstalled first-party C tests reuse **unchanged** B1-S0 source-owned Capture/optional Render SPSC, B0 independent Render SRC, capture-only B1-B1 FIR33 BF, original S2 layout/writer_begin/writer_append/writer_finish/decode/replay and B1-S1 SHA-256. No parallel APX3 serializer, CRC or parser.

- Physical record storage is **caller-allocated** at K * sizeof(fe_t3s1_slot) for K=1 or 2. Each slot has actual 5120-byte original S2 APX3, 200-byte original canonical FBS1 row and one uint32 byte count. The ring has NO phantom second physical slot when K=1; control sizeof is reported separately.
- A single exclusive worker first reserves a free physical slot, checks source IDs and generation, original Capture PCM FNV witness, optional source-owner Render PRESENT/ABSENT and source epoch; makes original one-frame S2 APX3 and CRC; checks decode, file SHA256 and previous **entire 200B canonical row** SHA256 chain. Only then can the original B1-S0 BF/source commit irreversibly advance. After this commit only bounded copies and one atomic release-publish of head may occur. No callback, allocation or I/O inside the BF worker.
- Source-owner ABSENT is an actual event, never inferred from silence or missing timestamps. An ABSENT event generates an original S2 file with render_channels=0. PRESENT generates an original S2 file with real Render PCM and render_channels=1. Full original canonical FBS1 metadata retains global Capture sequence, per-file local APX3 sequence=1, ids, slot map, PCM witness and exact SHA chain.
- The outboard callback identity and owner context are **pinned at initialization**; foreign callback/context requests fail closed before ACK. A **separate** outboard consumer acquires a stable slot with atomic SPSC, checks original first-party S2 decode and replay, FBS1 and PCM digest continuity before a test-only external sink. Full ACK/tail advance requires accounting exactly APX3 plus 200B row bytes. Partial or torn sink returns failure and withholds ACK. External consumer-side retries require idempotent identity; a failed write may already expose partial bytes and this stage does **NOT** establish transactional disk storage.
- Historical original B1-S1 24-slot APX3 archival bank, frozen S0/T0/T1/T2, deployed src/include/CMake, and public 2.x defaults remain unchanged.

## Compiler memory model / 内存、栈和容量边界

Compiler sizeof(fe_t3s1_slot) is expected to be exactly 5,324 B (5120 + 200 + uint32), two physically allocated slots 10,648 B. The C-qualified control sizeof(fe_t3s1_ring) is ABI-specific and separately measured; the test explicitly reports both one-bank and two-bank control-plus-record-slot accounting and actual externally accounted APX3+row transfer bytes. External sink's retained memory is not measured or counted in stage ownership. Original B1-S0 physically reserves **four** Capture and four Render slots even if source logical depth is 2; the stage must not fake depth-scaled memory savings. The BF worker has a separate original 5,120 B stack-local S2 preflight scratch. Its real stack/thread stack, original BF state and rollback work, original fixed source queue, producer/consumer task data, outboard external bytes and total process RSS are NOT in the compact stage-owned number. This is **not** a measured whole firmware RAM budget or an automatic 192KiB pass.

No rolling on-disk crash-consistent archive, persisted FBS1, real ADC/DAC clock, full SSC305 RAM, 10ms scheduler p99, stack high-water, thermal/power, HIL [#58](https://github.com/jiying2007/audio-pipeline/issues/58) or public SDK qualification. T3-S2 durable rolling persistence, T3-S3 whole-process resources/latency, and T3-S4 real SSC305 HIL remain independent.
