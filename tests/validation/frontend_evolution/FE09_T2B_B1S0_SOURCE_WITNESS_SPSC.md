## Precise source and race model

- **Two physical-independent logical owners:** exactly one Capture producer, an optional **independent** Render-event producer and one consumer worker. For render-enabled mode, worker requires *both* Capture and Render source-owner events bearing the **same software association sequence**; Render queue empty means **PENDING**, not loss, and worker returns EMPTY without consuming Capture or altering BF state.
- A Render event is either source-owner-supplied **real PCM** (copied to caller-owned SPSC slot and hashed) or explicit `REFERENCE_ABSENT` source-owner report (reason + **no** PCM). A source-owner report is **not cryptographically authenticated** and is not a real DAC/ADC clock diagnostic. Disabled Render is a separate configured mode and requires no producer; a lack of token in enabled mode is never interpreted as absent.
- Each Capture contains truly submitted source PCM copied from its caller (research source data generated deterministically in tests); correct logical source ID, generation, strictly contiguous positive `uint64` sequence, memory disjointness and exact 10ms sample count are mandatory. Render has a distinct source ID, generation and event sequence. Source epoch is separately checked and can advance only on an explicit Render GAP after an absent event; Capture gaps never quietly preserve mic BF history. SPSC ring depth **2/4**, 32-bit unsigned head/tail with acquire/release, source PCM copied before publish, worker acquires before reading; overflow near `UINT32_MAX` is tested with actual 24-frame producer/worker traffic. No runtime heap, mutex or file I/O.
- B0's first-party `fe_t2b_b0_capture` retains 16/32/48 kHz N-mic SRC+FIR33 BF **independently of Render availability**. The optional Render SRC consumes *only physically supplied test-source Render PCM*. Its local **delivered-render ordinal** starts at 1 and is independent of global association sequence; a source-owner gap resets only real reference histories. This software source identity says nothing about an actual shared ADC/DAC sample-zero or AEC delay.
- A B1-S0 worker checks exact source-event seq, producer hash, alias and output bounds **before** committing first-party BF. Render can process into an **unpublished temporary output** before Capture; B0 Capture is transactional. If BF rejects, restore Render adapter snapshot, release no SPSC tail and modify no user beam/reference/receipt. On an explicit owner-ABSENT token, Render history does not advance and reference output is not written. A late/duplicate reference cannot retroactively alter an already accepted frame.
- Source ID+generation checks are a *logical software owner contract*, not cryptographic trust, signed hardware-source provenance, a true DAC dropout detector or physical clock alignment. The caller must enforce exclusive ownership and no rebinds; this test facade cannot prevent an arbitrary hostile caller with reused source credentials from invoking its test API.

## Actual C qualification and failure matrix

The noninstalled C test includes the unchanged first-party threaded synthetic scene generator (C1, C2-ULA, C4-ULA, C4-UCA). It actually runs **4 arrays ×3 rates (16/32/48 kHz) ×2 SPSC depths ×2 Render configurations =48** concurrency configurations, each with **24 real Capture frames**. Both real pthread source owners (when Render enabled) fill bounded queues before worker starts, exercising E_FULL; the worker checks an actually populated Capture queue with an empty Render queue and must **not** mistake it for an absent token. Real signed-by-interface absent events then permit BF progress, actual Render events resume with explicit reference-only gap. Output is compared **bit-for-bit within the same ISA** to a wholly independent first-party B0 mic-only BF oracle for each actual frame; original first-party Render resampler acts only on delivered PCM.

Actual negatives include wrong ID/generation, source sequence gaps, wrong lengths, alias/null sources, forbidden rendered source after disabled configuration, fake absence reason, duplicate/stale events, empty queue and post-start wrap-counter reseed. An independently created **actual queued Capture+Render pair** is also run through a test-only first-party BF state corruption **after the real Render SRC has been processed**: the operation must reject with both SPSC tails, the B0 adapter's complete Render history, BF memory, external outputs and receipt byte-for-byte unchanged; restoring the test fixture must then process that same real pair successfully.
