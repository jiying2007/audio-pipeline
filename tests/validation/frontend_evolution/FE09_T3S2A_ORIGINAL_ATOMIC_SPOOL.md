## Ownership and original code / 所有权与原始字节

Actual callback type is the *unchanged* first-party `fe_t3s1_outboard_sink`. It may only be passed as the pinned sink when original T3-S1 ring initializes; the BF/Capture/source worker never executes a callback or syscall. Only one dedicated outboard owner calls `fe_t3s1_drain_one` and the adapter. It rejects foreign callbacks/context or a short ACK, and never advances original SPSC tail until exact accounting.

One committed file is an **outer storage envelope**, exactly `original 200-byte canonical FBS1 row || original <=5120-byte first-party S2 APX3 file`. The inner APX3 remains byte-for-byte original codec header/CRC/PCM/replay; `fe_s2_decode` and `fe_b1s1_sha256` are linked as real first-party implementations. This stage never creates an APX3 fork, second parser/CRC algorithm, modified frame stream, fabricated ADC clocks, Render silence/absence equivalence or new file format pretending to be an APX3 stream.

Records are named by original verified global Capture sequence, not the per-file APX3 local sequence (always one). Bind pins immutable source generation, capture/render owner IDs, input rate, C1/C2-ULA/C4-ULA/C4-UCA permutation, caller-owned dedicated directory descriptor/device/inode, exact user ownership and permission. A configurable hard quota (1..16 one-frame records) stops unbounded spool growth. No automatic rolling, ring skip/eviction or silent recorder gap.

## Commit/ACK ordering / 写盘及原子确认

1. On the outboard consumer, validate original 200B FBS1 SHA, previous *whole-row* SHA256, actual first-party APX3 SHA/CRC/decode, mapping, source owner IDs/epoch, local/global sequence and Render PRESENT/owner-reported ABSENT. Reject any conflict before changing published files or S1 ACK.
2. Open an immutable dedicated temporary pathname with O_CREAT|O_EXCL|O_NOFOLLOW|O_CLOEXEC; write *exact* canonical row followed by original S2 APX3 bytes with checked short writes; synchronize the new file.
3. Publish an immutable final name using **POSIX `linkat` with no replace**, then unlink the temporary link and synchronize the directory. This is atomic name creation, a deliberate no-clobber equivalent to unsafe replace-rename. Same sequence under different bytes can never silently replace the prior file. Failed syscalls or injected faults withhold ACK.
4. Reopen through O_NOFOLLOW, verify regular single-link file and exact byte length, re-read/compare the original FBS1 and APX3 bytes, independently call the same first-party decode+hash, and acknowledge exactly `200 + original APX3 length` bytes *only* on complete host transaction success. Fsync and readback are POSIX research controls, NOT a real power-cut test.
5. Crash injection after link-at-publication may expose both final and temporary hardlinks with the same inode: recovery permits deleting only the **verified same-inode link**, re-syncs the directory, rehashes completed original bytes and idempotently ACKs. Torn unpublished temp alone is quarantined and rejected; future source ACK is withheld, never silently advanced.
6. A new process can inventory a finite contiguous directory after restart, verify **each** historical original FBS1 row/previous-row SHA chain and original APX3 first-party codec, reject gaps/foreign files/symlinks/corrupt/conflicting records, recover the last owner sequence, and idempotently re-ACK only the exact latest retained identity. This does not recover unsupplied/missing source PCM after an actual device crash.
