## Frozen-source architecture / 设计原则

This is a **hosted software research** C implementation of a **one-frame original private S2 APX3 file per actual source Capture frame**. It does NOT implement durable POSIX writes, 128-frame rolling append, on-device real-time 192 KiB memory optimization, hardware ADC/DAC clock authority or release-ready recorder.

1. B1-S0 first-party SPSC real producer frames (Capture PCM and optional logical Render-owner events) remain immutable until worker advances its tail. B1-S1's exclusive worker **peeks** and copies the actual queued source PCM *before* consumption; it validates exact source generation, positive contiguous Capture association sequence, captured PCM FNV64, optional real Render owner-reported PCM/epoch/absence reason, physical-to-PCM-slot mapping and bounded source frame sizes. It never regenerates PCM from synthetic tests inside recorder logic or turns an empty Render queue into an absent token.
2. First-party unmodified `fe_s2_writer_begin → fe_s2_writer_append → fe_s2_writer_finish` writes **one complete and CRC-validated APX3 schema2** to a separate preallocated scratch arena. Its local `sequence=1` is required by the frozen S2 codec even for global Capture #N>1; external row maps `global_seq = chunk_global_start + apx3_local_seq - 1`. Separate real paired Capture+Render files have `render_channels=1`, while disabled/owner-reported absent Render uses complete `render_channels=0` files; no dummy Render samples or per-frame S2 header reinterpretation.
3. A 200-byte **canonical little-endian** row per complete file binds original input rate/mics/capture slot bijection, source generation, Capture and Render logical IDs and epochs, owner Render event and absence reason, global positive Capture seq, local APX3 seq 1, exact source PCM FNV64, actual file SHA256, SHA256(previous canonical manifest row) and SHA256(current canonical row prefix). All row offsets/byte widths are declared in `fe09_b2s3_t2b_b1s1_source_chunks.h`; no host struct padding or nondeterministic JSON serialization, no file IO, no signing key or claim of cryptographic source authentication. Hashes detect unauthorised bytes *relative to pinned immutable evidence*, not an adversary rewriting both file and manifest.
4. Only after source/codec/row/hash preflight passes does worker run the frozen `fe_b1s0_process_one` and original `fe_t2b_b0_capture` SRC+FIR33 path. Any rejection keeps old queue tails, B0 capture+reference histories, all old committed APX3/manifest bytes and external BF/reference/result unchanged. After successful BF commit, only nonfailing bounded memory copies and integer assignments publish the already prepared file/row; no file I/O, allocation or post-commit fallible CRC operation.
5. **Dedicated anti-race invariant:** after the first-party B1-S0 worker releases SPSC Capture tail, the producer may immediately overwrite the old slot. Therefore B1-S1 must never dereference `cap/ref` pointers after `process_one`; it takes the global sequence from the worker-owned already-committed `q->processed`. Source metadata/PCM/row are frozen *before* tail publication.
6. Verification uses **original first-party C** `fe_s2_decode` and `fe_s2_replay` visitor on every complete file to compare the byte-level LE Capture and real Render PCM source FNV64. It independently rehashes exact original APX3 bytes and canonical SHA256-linked rows. Python's standard `hashlib.sha256` and `zlib.crc32` perform a **separate byte-level check** on one actual C-emitted C4-UCA, 48k, Render-present APX3 file and manifest row; this does not replace the actual C codec/decoder tests.

## Actual scenarios / 真实执行矩阵

C1 / C2-ULA / C4-ULA / C4-UCA × 16/32/48 kHz × actual Capture/Render SPSC depth2/depth4 × optional Render owner 0/1 = **48 source/recorder configurations**. Each contains **24 genuine Capture source submissions, BF commits and 24 independently completed/replayed original S2 files** (1152 files per target). For enabled Render, actual source-owner ABSENT token ranges yield Capture-only S2 files; real Render ranges yield paired S2 files. The test's separate BF oracle uses original first-party SRC+FIR33 and only deterministic test PCM, with same-ISA Float32 comparisons. The recorder receives **exclusively** the previously copied actual SPSC PCM.

Mandatory negative controls include absent-but-no-event (PENDING, never synthetic reference), owner source/sequence/epoch mismatch and queue backpressure through predecessor, real post-Render / pre-mic-BF injected failure preserving original uncommitted chunk+manifest and exact retry, SHA256 empty/`abc` known vectors, corruption of APX3 header/PCM/frame CRC, canonical row magic/sequence/source hash/physical permutation/previous chain/current digest, shortened source file, omitted last chunk, global seq overflow and stable no-mutation verification failures. Tests explicitly reject non-real/corrupt sources; no source substitution.

Native, ASan+UBSan, ARM32/QEMU and native TSan each compile/run **actual changed C** twice, source-pin all original B1-S0/B0/S2/2.x code, hash compiler+ELF and retain a 30-day four-member `SHA256SUMS / receipt.json / collect.log / verify.log` Artifact. Cross-ISA raw BF Float32 equality is **not** required. Empty/failure artifact preserves a negative `NOT_ADMITTED` verdict.
